## 一、今日完成内容

### 1. 员工管理——会员等级联动优化

#### 1.1 表格去除会员等级列
- 员工管理表格移除"会员等级"列，保持表格简洁
- 会员等级仍可在新增/编辑弹窗中设置，详情弹窗中查看

#### 1.2 编辑权限进一步收紧
- **11管理员（一号）**：可编辑所有员工 ✅
- **01管理员（三号）**：只能编辑普通用户（role=0），**不再能编辑自己**
- 简化 `canEditRow()` 逻辑：`adminLevel===1` 全部可编辑，`adminLevel===3` 仅 `row.role===0`

#### 1.3 新增员工与会员表的联动规则
- **新增员工**：管理员设置会员等级后，仅保存到 `sys_user.member_level`，**不立即创建 Member 记录**。等员工自行注册时再写入会员表
- **编辑员工加会员等级**：`syncMemberLevel()` 立即创建/更新 Member 记录
- **编辑员工清除会员等级**：同步删除 Member 记录
- **删除员工**：级联删除对应的 Member 记录（`member_no = "M" + username`）
- **删除会员**：不影响员工表（单向级联）

#### 1.4 自行注册时的会员记录处理
- 员工自行注册时，先检查 Member 是否已被管理员通过编辑功能创建
- 若已存在 → 更新姓名和电话；若不存在 → 新建 Member 记录
- 修复了 `Duplicate entry 'M000000005' for key 'member.member_no'` 主键冲突 Bug

### 2. 电话校验误报修复

- **问题**：编辑员工会员等级保存时，提示"该电话号已在其他表中使用"
- **根因**：`update()` 中第一个校验正确排除了当前用户，但第二个 `isPhoneExists()` 又去 `sys_user` 表查了一遍，查到自己的号码就误报冲突
- **修复**：第二个校验改为直接查 `member` 和 `supplier` 表，不再重复查 `sys_user`

## 二、开发中遇到的问题与解决方案

### 问题1：syncMemberLevel 密码检查导致编辑后会员不显示

- **问题描述**：员工 susu 明明设置了会员等级，但会员表中不显示
- **根因**：在 `syncMemberLevel()` 中添加了"只有已注册用户才创建 Member"的检查。新增员工时原本就不调用此方法，但编辑时该方法会被调用，未注册员工的 Member 被错误拦截
- **解决方案**：移除 `syncMemberLevel()` 中的密码检查。该方法仅在 `update()`（编辑路径）被调用，管理员主动编辑就应该立即生效。新增员工的延迟创建由 `addEmployee()` 不调用 `syncMemberLevel()` 来保证

### 问题2：员工自行注册时 Member 主键冲突

- **问题描述**：管理员编辑未注册员工设置了会员等级（syncMemberLevel 创建了 Member），员工自行注册时再次 `insert` 同一条 Member 记录，触发 `Duplicate entry 'M000000005'`
- **根因**：自行注册代码中直接 `memberMapper.insert()`，未检查 Member 是否已存在
- **解决方案**：注册时先 `selectByMemberNo()` 检查，若已存在则 `update`（补全姓名电话），若不存在则 `insert`

### 问题3：背景效果不明显

- **问题描述**：暖色粒子在暖色背景图上完全看不见；光束太淡；光斑太透明
- **解决过程**：经过三次迭代增强——粒子→大光斑→加大尺寸+增加数量+提高透明度+新增光带
- **最终方案**：使用大尺寸（80-180px）白色柔光光斑 + 5道高亮光束 + 30颗带三层光晕的闪烁亮点 + 2条交替扫过光带

### 问题4：cpolar 网址显示旧版本

- **问题描述**：本地 localhost 显示最新修改，cpolar 生成的公网网址仍显示旧版
- **根因**：cpolar 隧道指向后端 8080 端口，后端提供 `static/` 目录中上一次 `npm run build` 的产物
- **解决方案**：每次修改前端代码后执行 `npm run build`，构建产物输出到 `backend/src/main/resources/static/`，重启后端即可生效
