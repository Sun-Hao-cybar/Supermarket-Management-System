### 2. 编辑对话框——手机号校验误报修复（员工/会员/供应商三表）

#### 2.1 问题描述
- 编辑员工备注时，提示"该电话号已在会员中使用"
- 编辑会员备注时，提示"该电话号已在员工中使用"
- 编辑供应商备注时，同上

#### 2.2 根因分析
三张表的 `update` 方法在保存时均全量做手机号唯一性检查：
- **员工表**：员工=会员时手机号共享，`checkPhoneUnique()` 在会员表中查到自己的手机号就误报
- **会员表**：会员=员工时，`checkPhoneUnique()` 在员工表中查到自己的手机号就误报
- **供应商表**：`checkContactPhoneUnique()` 同样做了全量检查

#### 2.3 修复方案
| 文件 | 修复方式 |
|------|---------|
| `SysUserService.update()` | 检查会员表时排除自己的 `memberNo == "M" + username` |
| `MemberService.update()` | 只有手机号变化时才做唯一性检查 |
| `SupplierService.update()` | 同上（新增 `selectById` 查询现有记录） |
| `SysUserService.add/update/delete` | `@CacheEvict` 增加 `"memberList"`，修复会员表缓存不同步 |

### 5. 白色小猫智能体（Cat Agent）— 完整设计与实现

#### 5.1 架构设计（设计方案 B：前端组件 + 后端代理 DeepSeek API）

```
用户提问
  → ① 本地知识库（40+ QA，动作词 3x 权重，<1ms）
  → ② 自学习缓存（之前 AI 答过的问题，localStorage，<1ms）
  → ③ DeepSeek API（System Prompt 内嵌完整参考知识库，有据可依）
```

**关键决策**：
- DeepSeek API Key 存在后端 `application.yml`，前端不暴露
- 小猫组件仅在 `/layout/*` 路由下可见（登录后），Login 页不展示
- 用户行为模式设置存 `localStorage`

| `dto/ChatRequest.java` | 对话请求：message + history |

## 二、开发中遇到的问题与解决方案

### 问题1：编辑员工会员等级后会员表不显示 / 取消后不消失

- **问题描述**：员工管理中给员工设置/取消会员等级后，切换到会员管理页面看不到变化
- **根因**：`SysUserService` 的 `syncMemberLevel()` 直接用 `memberMapper` 操作会员表，绕过了 `MemberService` 的 `@Cacheable("memberList")` 缓存。数据已入库但缓存未清
- **解决方案**：`SysUserService.add/update/delete` 的 `@CacheEvict` 全部增加 `"memberList"`

### 问题2：编辑采购单"请求失败"

- **问题描述**：新增或编辑采购单，填写完点击确定，弹出"请求失败"
- **根因**：前端日期选择器格式 `YYYY-MM-DD`（如 "2024-01-15"），后端 `@JsonFormat` 要求 `yyyy-MM-dd HH:mm`（需时间部分）。Jackson 反序列化失败 → HTTP 400
- **解决方案**：后端 `PurchaseMain.purchaseTime` 注解同步为 `yyyy-MM-dd`

### 问题4：智能体 AI 幻觉严重 — 编造不存在的功能

- **问题描述**：用户问"如何查询员工信息"，AI 回答"点击编辑按钮修改后保存"；问"导出商品"回答"查看商品"的内容；问"导入商品"完全不匹配
- **根因**：① 知识库缺少"查看/导出/导入"条目 ② 关键词权重相同，动作词（导入/导出/添加）和主题词（员工/商品）平分秋色 ③ DeepSeek System Prompt 太笼统，没有具体参考信息
- **解决方案（四轮迭代）**：
  1. 补充 Member/Goods/Supplier 的查看/导出/导入条目，覆盖全部模块 × 全部操作
  2. 动作词 3x 权重机制：导入/导出/添加/编辑/删除/查看等 18 个动作词得分 ×3，确保"如何导入员工"(score=8) > "如何查看员工"(score=4)
  3. ≥2 关键词门槛 + 平局优先选匹配数多的，不再盲目放弃
  4. DeepSeek System Prompt 注入完整 40+ 条参考知识库，作为唯一权威来源，强制"不知道就说不知道"

### 问题5：知识库匹配张冠李戴 — 缺动词的模糊问法

- **问题描述**："如何商品信息"缺动词，被匹配到编辑条目而非查看条目
- **根因**：子串匹配无法区分用户意图，两条目关键词重叠时平分
- **解决方案**：匹配率 × 权重公式（v3）→ 动作词 3x 权重（v4），根本性拉大区分度

### 问题6：小猫视频圆形有黑边

- **问题描述**：MP4 视频本身带黑边/暗角，`border-radius:50%` 裁剪不够彻底
- **根因**：原 `.cat-avatar` 用 `overflow:visible`（因为气泡和角标在内部需要显示），视频黑边未被裁剪
- **解决方案**：重构模板结构为 `cat-wrapper > cat-avatar + cat-bubble + cat-badge`，`.cat-avatar` 使用 `overflow:hidden` 彻底裁剪，气泡和角标移出裁剪区。视频再放大 108%（`width:108%; height:108%; margin:-4%`）确保黑边完全不可见

### 问题7：Cpolar 公网访问无智能体

- **问题描述**：Cpolar 生成的公网网址登录后看不到小猫智能体
- **根因**：Cpolar 隧道指向后端 8080 端口，后端静态文件是旧构建版本
- **解决方案**：`npm run build` 重新构建前端，输出到 `backend/src/main/resources/static/`，重启后端

### 问题3（旧）：手动输入的采购总价保存后变成商品总价

- **问题描述**：主表新增时手动输入采购总价（如含运费 1200 元），保存后显示变成了明细自动计算的商品总价（如 1000 元）
- **根因**：`recalcAllMainTotals()` 在页面数据加载后调用 `detailTotalsMap` 汇总，用明细的 `totalPrice` 覆盖了主表的 `totalPrice`
- **解决方案**：`recalcAllMainTotals` 和 `recalcMainTotals` 只更新 `totalNum`（数量汇总），不再触碰 `totalPrice`
