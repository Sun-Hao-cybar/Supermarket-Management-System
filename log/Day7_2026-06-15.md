#### 1.3 数据库 E-R 图设计

使用 Graphviz dot 引擎自动布局绘制 Chen 式 E-R 图：

| 要素 | 形状 | 数量 |
|------|------|:---:|
| 实体 | 矩形（蓝色表头 + 字段列表） | 6 个 |

| 连线 | 实体↔联系，标 1:N / 1:1 | 10 条 |

6 个实体：
- supplier（供应商）、goods（商品）、member（会员）
- sys_user（系统用户）、purchase_main（采购主表）、purchase_detail（采购明细）

5 个联系：
- 供应（supplier→goods, 1:N）
- 包含（goods→purchase_detail, 1:N）
- 采购（sys_user→purchase_main, 1:N）
- 注册（sys_user→member, 1:1）
- 拥有（purchase_main→purchase_detail, 1:N）

### 2. 系统 Bug 修复

#### 2.1 会员管理——新增时日期时间被覆盖

**问题**：新增会员时选择了日期时间，点击确定后自动更改为当前时间。

**根因**：`MemberService.add()` 中当 `registerTime == null` 时自动设为 `new Date()`。前端日期选择器 `value-format="YYYY-MM-DD HH:mm"` 发送的字符串格式与后端 `@JsonFormat(pattern = "yyyy-MM-dd HH:mm")` 匹配，但在某些情况下 Jackson 解析失败导致 registerTime 为 null，触发服务层默认逻辑。

**修复**：确保前端日期格式与后端一致，同时保留服务层的 null 兜底逻辑作为保护。

#### 2.2 商品编号重复——友好提示

**问题**：商品编号重复时系统直接报错（500 错误），而非友好提示。

**根因**：`GoodsService.add()` 中的重复检查 `selectByGoodsCode()` 在并发场景下可能漏检，导致 MySQL 的 UNIQUE KEY 约束直接抛出 `DuplicateKeyException`，被全局异常处理捕获后返回 500。

**修复**：
- 在 `GoodsService.add()` 中增加 `try-catch` 捕获 `DuplicateKeyException`
- 捕获后返回 `Result.error("商品编号已存在，请重新输入")`
- `GoodsController.add()` 的异常处理同样补充重复键异常捕获

#### 2.3 Excel 导出优化

**问题**：
- 导出的 Excel 表包含 `id` 列（自增主键），不应暴露给用户
- 商品编号、员工编号、会员编号、供应商编号等业务编号应保留
- Excel 表头第一行汉字显示不完整（列宽不够）

**修复**：
- 各 Controller 的 export 方法中，`headers` 和 `fields` 数组移除 `id` 字段
- 保留各表的业务编号字段：`goodsCode`、`username`（员工编号）、`memberNo`、`supplierCode` 等
- `ExcelUtil.exportExcel()` 中 CJK 列宽计算公式调整为 `headers[i].length() * 3.5 * 256 + 2048`，增大缓冲
- 在 `autoSizeColumn()` 之后额外增加 20% 宽度裕量

#### 2.4 Excel 导入修复

**问题**：
- 编辑完 Excel 表后导入显示"导入失败"
- 员工表 Excel 导入失败——未做管理员过滤

**根因**：
- 部分 Controller 的 import 方法在解析数值列时，对空单元格的处理不当（`Number` 类型转换 `null` 时抛出 NPE）
- 员工导入未限制管理员数据

**修复**：
- 各 import 方法增加空值保护：`Number` 类型转换前先判空，空值设为 0 或 null
- `SysUserController.import()` 中增加 `role` 检查：`role == 1` 的行返回明确错误"管理员信息不允许通过Excel导入"
- `PurchaseMainController.import()` 中 `userName` 列增加超时处理
- `PurchaseDetailController.import()` 中 `goodsCode` 查找失败时返回明确行号提示

#### 2.5 会员管理——增加 Excel 导入

**问题**：会员管理缺少 Excel 导入功能，其他模块（供应商/商品/员工/采购）均有。

**修复**：
- `MemberController` 新增 `POST /member/import` 接口
- 支持导入 6 列：`memberNo`、`name`、`phone`、`level`、`registerTime`、`remark`
- 前端 `Member.vue` 增加"导入会员Excel"按钮和文件选择逻辑
- 导入时自动校验会员编号唯一性、手机号唯一性、会员等级合法性

#### 2.6 Excel 导入——时间字段解析

**问题**：导入 Excel 时，表中填写的时间被更改为当天时间。

**根因**：`ExcelUtil.getDate()` 在解析字符串格式的日期时，若格式不匹配（如用户使用中文格式"2024年6月15日"），返回 null，导致 Controller 中设置默认值 `new Date()`。

**修复**：
- `ExcelUtil.getDate()` 增加更多日期格式支持：`yyyy年MM月dd日`、`yyyy/MM/dd HH:mm`、`yyyy.MM.dd`
- 各 Controller 的 import 方法中，日期字段解析失败时保留 null 而非默认当天
- Service 层根据业务需要决定是否使用默认时间

## 二、遇到问题及解决方案

| 问题 | 解决方案 |
|------|---------|
| E-R 图文字太小打印不清 | 多次调整画布尺寸和字号，最终使用 1600×2500 画布 + 36pt 字号 |
| Chen 式 E-R 节点过多导致图幅过宽 | 改用实体矩形内嵌字段 + 菱形联系的折中方案 |
| Graphviz 布局横向过宽 | 使用 `rank=same` 约束行对齐 + invisible edge 控制纵向流 |
| docx-js ImageRun 尺寸单位不明确 | 通过解包 XML 读取 `wp:extent` 反推换算比例（~9525 EMU/单位） |
| Word 文件锁定导致无法覆盖 | 输出到临时文件名 `_课设报告_new.docx` |
